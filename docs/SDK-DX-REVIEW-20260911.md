### 1. TypeScript / JavaScript

The manifest exports ESM and declarations, with no CommonJS export branch (`L/typescript/package.json`). S's older installed tarball was used for the arithmetic/error probes.

```ts
import { createClient } from '@openrouter/sdk';
const client = createClient({ auth: { apiKey: token } });
const key = await client.getCurrentKey();
console.log(key.status);
```

**Actual experience.** The native object-literal surface is a strength. `getCredits()` needs no input; passing a signal uses `getCredits({}, { signal })`. A sole success is already directly readable; `credits.data.data.total_credits` has one HTTP wrapper and one real source envelope. `createKeys({ body: { name: 'Demo' } })`, omitted properties, and `limit: null` are straightforward. Integers use `bigint`; general numbers use `JsonNumber`.

**Strongest friction — medium bug.** Installed JavaScript evaluates `credits - usage` as `74.75`, losing the fixture's final decimal digits; `credits + JsonNumber.parse('1')` concatenates to `100.500000000000000011`. TS rejects arithmetic statically, but JS has no such protection. `JsonNumber` defines `toString()` and a rejecting `toJSON()`, but no numeric-coercion guard (`S/typescript/json.ts:73–128`). [Repro/output](../target/sdk-dx-review-20260911-01/probe-results/javascript-public-package/stdout.txt), [TS diagnostics](../target/sdk-dx-review-20260911-01/probe-results/typescript-newcomer-diagnostics/stdout.txt). Add a runtime coercion guard and a documented exact-decimal interoperability recipe; retain explicit token display.

**Errors/configuration/lifetime.** Operation-specific guards narrow declared errors; arbitrary promise rejection remains `unknown`. The controlled 401 is recognized, while malformed 401/200 bodies are `response-decoding` failures. An undeclared credits 429 is `unexpected-response`, not a typed credits API variant. A supplied credential callback ran once per request. Setting `OPENROUTER_API_KEY` without `auth` did not send a request. AbortSignal is the timeout/cancellation mechanism; there is no SDK timeout option or retry loop in this pin. Standard streams use `AsyncIterable`; unused streams need explicit abort/iterator release.

**Discovery/docs.** L's read/factory are at `typescript/operations.ts:190,280–284`. ### 3. Go

**Install/setup.** L module is `github.com/openrouter/sdk-go`, package `sdk`. Its separate consumer uses a local `replace`. Go **1.23**, no non-standard-library dependency. Assume `sdk "github.com/openrouter/sdk-go"`, a caller-owned `ctx`, and an enclosing function returning `error`.

```go
if err != nil { return err }
key, err := client.GetCurrentKeyData(ctx)
if err != nil { return err }
```

Use `key.Data` for the source envelope; manage a reusable client's idle connections at application shutdown. The short excerpt ends at the checked read rather than hiding construction errors.

**Actual experience.** `GetCreditsData(ctx)` is a meaningful convenience: it returns the payload without a type assertion. The canonical `GetCredits` preserves status/media metadata. `credits.Data.TotalCredits.String()` is the exact field. **Strongest friction — deliberate value-model tradeoff.** `Number` and `Integer` require token parsing; their zero values are invalid. Optional-nullable fields need `PresenceSome`, `PresenceNull` or zero absence; required nullable values use `Nullable`. That is more learning than pointers/ordinary numeric fields, although it preserves distinctions that pointers alone would lose. A `math/big.Rat` bridge computed the fixture balance exactly. Named models work with **standard `encoding/json`** through their source codec; standalone presence wrappers intentionally reject it. [Installed-module probe](../target/sdk-dx-review-20260911-01/probe-results/go-interop-run/stdout.txt); `S/go/models.go:1242,1362`, `json.go:34–49`.

**Errors/lifetime.** The 401 type is `*sdk.GetCreditsStatus401`; SDK errors retain `Kind`, cause, status and bounded capture. `context` controls the complete call and any stream; client `Timeout` is also available. `CloseIdleConnections` forwards even to a supplied transport that offers that method (`S/go/http_runtime.go:53–109`). Standard streams use `Next/Value/Err` and `defer Close()`; no auto-pager or retry loop is introduced.

**Advanced/docs.** The v3 tree keeps `Label string` and puts broad values only in dynamic children, although `Optional[[]Nullable[Value]]` is visibly elaborate. Native `go doc`, compact operation lists and checked constructors are useful; the README still assumes an already configured client. Provide a complete local `go.mod` plus the minimal constructor/context/read recipe. ### Configuration, credentials and request ownership

- **Default server:** the fixed HTTPS URL is an OpenAPI server default, not an application setup requirement. Controlled S TS/Go/C++ probes captured it without an override; L has an additional TS/JS source-default receipt. Other L native staging checks use explicit loopback verification plumbing and are not proof of live network reachability.
- **Credentials:** `apiKey` is the source scheme name for HTTP bearer. It does not mean a custom API-key header. Explicit constructors are already implemented in every target. Application env lookup in L is a real convenience of the demo programs, not automatic SDK env discovery.
- **Callback precedence:** existing credential providers are explicit caller policy. The TS callback probe invoked its bearer provider once per call. No env fallback exists in S/B/G/L to merge with or override a callback. Later v1 implementations make a whole explicit credential argument authoritative; their all-twelve qualification is covered by the post-review native/canonical receipts, not by the L probe matrix.
- **Security alternatives:** most documented profiles choose a first complete supplied alternative; Ruby in these pins requires an explicit index when more than one alternative exists. The OpenRouter selections use one bearer scheme, so the five-/six-operation demos do not exercise a general OR/AND matrix. Refer to native protocol receipts for those separate cases.
- **Request/response validation:** native constructors/types do not encode every schema rule. Codecs validate at HTTP boundaries and commonly revalidate mutable state on encode. A malformed declared error body is a decoding failure, not a successful typed API-error decode. Consumers should handle both branches.
- **Business policy:** schema defaults are not automatically sent; date/format annotations do not imply arbitrary language-specific coercion. This is intentional fidelity. Examples should make omission versus application defaults explicit rather than imply a missing convenience is a codec defect.

### Timeout, cancellation and streaming idioms

These are the inspected runtime/profile interfaces, not stream operations present in S/G/L's selected HTTP surface. Streaming examples require a separately admitted stream operation. Native protocol guides linked above contain the broader execution receipts.

| Target | Call deadline/cancellation | Standard stream and lifetime idiom |
| --- | --- | --- |
| TS/JS | Caller `AbortSignal`, e.g. `AbortSignal.timeout`; no SDK whole-call timeout option | `AsyncIterable`; consume, return/break the iterator, or abort an unused stream |

### Files, forms, media and finite limits

All twelve expanded profiles have real native binary/part representations: Uint8Array, Python bytes/Part, Go `[]byte`/Part, Rust `Vec<u8>`/Part, Swift Data/parts, Java Bytes, C# byte arrays/part records, Kotlin ByteArray/Upload, Ruby Bytes/BytePart, PHP Bytes, Dart Uint8List and C++ Bytes. File names are metadata; they do not trigger filesystem reads. Request media choices and status/media response alternatives remain explicit, and response headers/links retain source semantics.

This is valuable protocol fidelity. It still creates app work: read the file, allocate the finite byte value, choose admitted media, construct metadata, handle limit failures and write downloaded bytes. Request “streams” in supported profiles are generally finite/buffered before sending; a Flow/Iterable input does not imply an unbounded upload pipeline. Positional and response multipart coverage differs by target and must be taken from that target's profile rather than a fleet-wide checkbox.

The common generated body ceilings in this workload are 8 MiB, with a 4 MiB profile described by Kotlin; part/item/header and validation budgets are also finite and differ. Client overrides generally only lower the generated ceiling. The TS probe requesting `maxResponseBytes: 8388609` failed before HTTP. This protects bounded work but is a practical obstacle for larger documents/downloads and long streams even when the source itself has no such size restriction. Recommend visible capacity settings in generated docs/configuration and clearly named large-file capabilities when they are actually implemented.

### Documentation, search and regeneration

**Documentation strengths:** public source-bound names are substantially better than opaque schema paths; source/native manifests retain operation IDs, pointers and spans; examples record declared versus synthesized origins. Native toolchains are respected: TypeDoc, Sphinx, go doc, Rustdoc, DocC, Javadoc, C# XML/HTML, Dokka, YARD/RBS, PHPDoc, dartdoc and Doxygen. **Generation workflow strengths:** explicit package/import configuration is real, as the S → B/G/L changes demonstrate. The source-default URL works independently of those identities. Ownership/check/preview and compatibility metadata support a reproducible edit–review–regenerate loop.
