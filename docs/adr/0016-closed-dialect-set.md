# Owned validation admits a closed set of dialects and lowers OAS 3.0 onto the same instructions

Only two dialect URIs are admitted: `https://spec.openapis.org/oas/3.1/dialect/base`, which OAS 3.2 also uses because there is no 3.2 base dialect, and JSON Schema 2020-12. OAS 3.0 Schema Objects have no profile of their own; they are lowered onto the same instructions. `nullable` affects only the type check on the same object, Boolean `exclusiveMinimum`/`exclusiveMaximum` modify the adjacent bound, and a Reference Object applies only its `$ref`, ignoring siblings. Custom dialects, `$vocabulary`, legacy `definitions`/`dependencies`/`$recursiveRef`, assertion-mode `format` and OAS 3.0's direction-dependent `required` are located errors. The backend schema view (`schema_view`) applies the same rules to model planning, so native types and validation never disagree.
