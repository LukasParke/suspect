# Pinned acquisition shells out to a sandboxed curl instead of an in-process HTTP client

`suspect acquire` runs one curl child process per HTTP hop (`/usr/bin/curl` or `curl.exe` by default, configurable via `curl_program`). It passes `--disable` so `.curlrc` is ignored and clears the environment. It disables proxies, netrc, retries, redirects and decompression, and uses `--raw` so suspect decodes chunking and enforces byte and header budgets itself. Credentials go over stdin. Every redirect and credential decision stays in Rust (`crates/suspect-ref/src/acquire/transport.rs`). A child process can be killed at the deadline even while stalled in DNS, TLS or header reads, which a blocking in-process client cannot guarantee, and `suspect-ref` stays free of an HTTP/TLS stack. The cost is a runtime dependency on an installed curl (tested against 8.7.1).
