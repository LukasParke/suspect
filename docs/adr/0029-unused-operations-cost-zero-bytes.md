# Generated SDKs are structured so an unused operation costs a consumer zero bytes

Each backend emits code so the toolchain's own elimination can remove operations, codecs, OAuth grants and stream machinery a consumer never references. That means ESM tree shaking, Go and C++ linker GC, Cargo features, R8 and IL trimming, Dart AOT, and conditional require or autoload. The rule, enforced against real toolchains by the `*_elimination` tests in `crates/suspect-codegen/tests/`: adding an unrelated operation must not grow a one-operation consumer, and shared runtime files stay byte-identical. This is why the generator emits per-operation units and self-contained descriptor literals instead of one central client table, which would be smaller to emit but would keep the whole API alive. Known per-language exceptions, such as Swift retention and shared validation tables, are pinned as measured outcomes in those tests.
