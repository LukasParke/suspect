## a. Executive summary

The published SDK and ours are two different **API shapes over the same wire API**. The published
SDK is a Speakeasy "globals + resource properties + pydantic" SDK: one `OpenRouter` class exposing
resource properties (`client.credits.get_credits()`), pydantic models with declared wire aliases,
a 22-class error hierarchy, automatic retry, and SSE streaming through `EventStream`. Ours is a
flat protocol-plan SDK: `Client`/`AsyncClient` with one keyword-only method per admitted operation
(`client.get_credits()`), frozen dataclass models with codec-enforced wire aliases, per-operation
typed `ApiError` subclasses, and **no** retry layer. Both sides preserve the response envelope and
both rename camelCase wire fields to pythonic names via declared aliases.

Counts: the published wheel exposes **111 unique wire operations** as 124 sync + 124 async methods.
Our emitted SDK covers **42**. Of the 91 operations in our source spec: **41 MATCH** published ops
(plus 1 EXTRA-OUR-SIDE op the published SDK lacks — `createCoinbaseCharge`), **47 are
MISSING-OUR-SIDE** (38 refused by admission with codes; **10 admitted but not emitted** — a
generator drop, ranked P0), 1 is absent from both sides, and 22 published ops are absent from our
source spec entirely (newer spec generation). Of the 41 matched ops, method names are identical for
14 and differ for 27 (flat operationId-derived names vs resource-scoped short names). The single
largest generalizable gap is op coverage driven by refusal codes (`http-path-parameters`,
`http-stream-item-schema-required`, `http-nullable-annotation`), followed by missing retry, and the
loss of `nullable: true` semantics from the OAS-3.0-style spec served as 3.1.

## b. Client construction & lifecycle

**Published — single class, sync + async fused** (`sdk.py`, `sdkconfiguration.py`):

```python
OpenRouter(
    api_key: Optional[Union[str, Callable[[], Optional[str]]]] = None,   # -> components.Security(api_key=...)
    http_referer: Optional[str] = None,          # SDK-global header, see section (e)
    x_open_router_title: Optional[str] = None,   # SDK-global header
    x_open_router_categories: Optional[str] = None,  # SDK-global header
    server: Optional[str] = None,                # named server: SERVERS = {"production": "https://openrouter.ai/api/v1"}
    url_params: Optional[Dict[str, str]] = None, # server URL templating
    server_url: Optional[str] = None,            # explicit base URL override
    client: Optional[HttpClient] = None,         # default httpx.Client(follow_redirects=True)
    async_client: Optional[AsyncHttpClient] = None,  # default httpx.AsyncClient(follow_redirects=True)
    retry_config: OptionalNullable[RetryConfig] = UNSET,
    timeout_ms: Optional[int] = None,            # per-request timeout, milliseconds
    debug_logger: Optional[Logger] = None,
)
```

- **No `AsyncOpenRouter` class exists** (`grep AsyncOpenRouter` over the wheel: 0 hits). Every
  method has an `*_async` twin on the same resource object; both httpx clients are constructed
  eagerly and owned together.
- Lifecycle: context manager (`__enter__`/`__exit__`, `__aenter__`/`__aexit__`) closes only
  non-caller-supplied clients; `weakref.finalize(close_clients, …)` backstop
  (`sdk.py:247-255`, `httpclient.py`).
- Retry default (applied in every method when `retries=UNSET` and `retry_config` unset):
  `RetryConfig("backoff", BackoffStrategy(500, 60000, 1.5, 3600000), True)` — exponential backoff
  500 ms → 60 s, exponent 1.5, max elapsed 1 h, `retry_connection_errors=True`, retrying **5XX**
  only (`credits.py:80-90`, `utils/retries.py`). Per-method override `retries=`; configurable
  status-code override list.
- Security: `components.Security(api_key=...)` → Bearer `Authorization` header
  (`components/security.py`, scheme_type "http" bearer). **No environment-variable fallback for the
  API key** on the published side; `get_global_from_env` env reads exist only for the three
  `OPENROUTER_HTTP_REFERER` / `OPENROUTER_X_OPEN_ROUTER_TITLE` / `OPENROUTER_X_OPEN_ROUTER_CATEGORIES`
  globals (`sdk.py:210-220`).
- Hooks: `_hooks.SDKHooks` (before_request/after_success/after_error) wired into every call.

**Ours — explicit sync/async duality** (`_client.py:309-317, 514-525`; `_runtime.py:491-497, 576-581`):

```python
Client(   # and AsyncClient with transport: httpx.AsyncBaseTransport
    *, auth: Mapping[str, Credential] | None | _OmittedAuth = _OMITTED_AUTH,  # {"apiKey": "..."} or provider callable
    server_url: str | None = None,
    server: int | str = 0,               # index or name into spec-declared server candidates
    server_variables: Mapping[str, str] | None = None,
    document_url: str | None = None,     # base for relative server URLs
    auth_alternative: int | None = None, # pick one security alternative explicitly
    transport: httpx.BaseTransport | None = None,
    max_response_bytes: int | None = None,
    max_capture_bytes: int = 4096,
    timeout: float | None = 30,          # seconds -> httpx.Timeout(30)
)
```

- `AsyncClient` is a **separate class** (vs published single-class duality); both share the same
  generated methods with the same names.
- Credentials: `auth` maps credential names to `str | BasicAuth | Authorization | CredentialProvider`
  (`_types.py:100-102`). Default (auth omitted) reads `OPENROUTER_API_KEY` from the environment
  (`_credential_env.py:38-58`) — **env fallback exists on our side, not on the published side**.
  Callbacks returning awaitables in the sync client are rejected
  (`http-async-credential-in-sync-client`).
- Transport: owned `httpx.HTTPTransport(trust_env=False, retries=0)` unless `transport=` supplied.
  **No retry layer of any kind** — no `RetryConfig`, no backoff, no 5XX retry (`_runtime.py:500`).
- Lifecycle: context manager + explicit `close()`/`aclose()`; open streaming responses tracked and
  force-closed on exit (`_runtime.py:503-530`); no weakref finalizer.
- User agent: `suspect/0.1.0 openrouter-compat/1.1.153 (python/x; openapi/3.1.0)`, overridable via
  `user_agent=` / `application_id=` on the base runtime; published sends Speakeasy's own UA string
  (`sdkconfiguration.py:44`).

| Concern | Published | Ours |
|---|---|---|
| Client classes | `OpenRouter` (sync+async fused) | `Client` + `AsyncClient` |
| Auth kwarg | `api_key=` (str or factory) | `auth={"apiKey": …}` (+ env default) |
| Base URL | `server=`/`server_url=`; `https://openrouter.ai/api/v1` | `server=`/`server_url=`; same production URL from spec `servers` |
| Retries | backoff 500 ms–60 s ×1.5, 5XX, conn errors | **none** |
| Timeout | `timeout_ms` (ms), per method override | `timeout=30.0` s, constructor only |
| Transport injection | `client=`/`async_client=` (protocol objects) | `transport=` (httpx BaseTransport) |
| Hooks / events | `SDKHooks` | none |
| Global headers at construction | `http_referer`, `x_open_router_title`, `x_open_router_categories` | absent |

## c. Composition: resource properties vs flat methods

Published — two-level resource properties (three for `beta.responses`), resource-scoped names:

```python
from openrouter import OpenRouter
client = OpenRouter(api_key="...")

resp = client.credits.get_credits()               # operation getCredits
resp.data.total_credits                           # pydantic model, envelope preserved
key  = client.api_keys.create(name="ci", limit=5) # operation createKeys
user = client.analytics.get_user_activity(request={"date": "2025-08-24"})  # request-object style
models = client.models.list(q="gpt")              # operation getModels
stream = client.chat.send(messages=[...], stream=True)  # EventStream[ChatStreamChunk]
```

Ours — flat methods on the client, operationId-derived names:

```python
from openrouter import Client
client = Client(auth={"apiKey": "..."})

resp = client.get_credits()                        # operation getCredits
resp.data.data.total_credits                       # Status200 envelope: .data is the {data: ...} JSON shape
key  = client.create_coinbase_charge()             # (createKeys not emitted — see section d)
user = client.get_user_activity(date="2025-08-24") # flat kwargs, no request object
models = client.list(include_disabled=True)        # operation id "list" becomes client.list
```

Composition differences in one line each:

- `client.credits.get_credits()` → `client.get_credits()` (resource flattened into the name).
- `client.api_keys.create(...)` → `client.create_keys(...)` (name derived from operationId, not
  resource+verb) — and because `createKeys` was not emitted, **no** equivalent exists today.
- `client.analytics.get_user_activity(request=GetUserActivityRequest(...))` →
  `client.get_user_activity(date=..., api_key_hash=..., user_id=...)` (request-object collapses to
  kwargs).
- `client.beta.responses.send(...)` (three-level nesting) → no equivalent (`createResponses` refused).
- Callability parity: all params keyword-only on both sides.

## e. Parameter shapes

**Published conventions** (verified across resource + operations modules; there is **no
`NOT_GIVEN`** in the wheel — all 172 "omitted" hits are docstring prose):

- Every parameter is **keyword-only** (`*` in every signature). Required body params (e.g.
  `messages` in `chat.send`) are keyword-only with no default; simple-optional params are
  `Optional[T] = None`; **tri-state optional** (absent vs explicit `null`) uses
  `OptionalNullable[T] = UNSET` with the `types.UNSET` singleton
  (`types/basemodel.py:31-36`: `OptionalNullable = Optional[T] | Unset`).
- Two param styles: flat kwargs (most ops) and a **request-object style** for parameter-heavy ops
  (`analytics.get_user_activity(request: operations.GetUserActivityRequest | …TypedDict =
  operations.GetUserActivityRequest(), …)`; `analytics.query_analytics` likewise). Request objects
  accept the generated pydantic model or the `…TypedDict` form (`utils.unmarshal` coerces).
- Every method additionally accepts the **cross-cutting kw-only tail**: `retries:
  OptionalNullable[utils.RetryConfig] = UNSET`, `server_url: Optional[str] = None`,
  `timeout_ms: Optional[int] = None`, `http_headers: Optional[Mapping[str, str]] = None`
  (`credits.py:15-24`).
- **Globals parameters**: `http_referer`, `x_open_router_title`, `x_open_router_categories` —
  **not present in the OpenAPI source** (they do not appear in `/tmp/openrouter-assembled-repaired.json`);
  they come from the published generator's globals configuration and are injected into
  `X-OpenRouter-*`/`HTTP-Referer` headers via `internal.Globals` + per-op `…Globals` pydantic
  models. **246 of 248 methods** carry them as explicit kwargs; the remaining 2
  (`analytics.get_user_activity` sync/async) carry them **inside the request object**
  (`operations.GetUserActivityRequestTypedDict` opens with `http_referer`, `x_open_router_title`,
  `x_open_router_categories` before `date_`) — i.e. every method receives the globals. At
  construction they can be set once for all ops (`sdk.py:147-160`) with env fallbacks
  `OPENROUTER_HTTP_REFERER`, `OPENROUTER_X_OPEN_ROUTER_TITLE`, `OPENROUTER_X_OPEN_ROUTER_CATEGORIES`.
- **Wire-name mapping**: python field name = snake_case of the wire name, with a declared pydantic
  alias when they differ. 75 of 649 component files use aliases; examples: python `api_key` ↔ wire
  `apiKey`, `base_url` ↔ `baseUrl`, `ml_app` ↔ `mlApp`, `instance_id` ↔ `instanceId`
  (`components/observabilityarizedestination.py:27-34`); python `date_` ↔ wire `date`
  (`components/activityitem.py:22-23`, renamed to avoid the `datetime.date` clash); python `type_` ↔
  wire `type` (keyword collision). Request/query/path param names in the matched ops are already
  snake_case on the wire (`workspace_id`, `start_date`, `file_id`), so aliases mostly apply to body
  fields and headers (`HTTP-Referer` ↔ `http_referer`).

**Ours** (`_client.py`, `protocol-plan.json`, `codec_runtime.py`):

- Every parameter is **keyword-only**; optional params are `T | Unset = UNSET` where the wire
  permits absence, and **required path params are keyword-only with no default**
  (`delete_file(*, file_id: models.DeleteFilePathFileId, workspace_id: … | Unset = UNSET)`).
- Request bodies are a single kw-only `body: models.XxxRequest2 | Unset = UNSET` (one dataclass per
  media type; `Request2` suffix disambiguates inline body schemas from named components).
- No cross-cutting method kwargs at all: **no `retries`, `server_url`, `timeout_ms`,
  `http_headers` per method**; those live on the client (constructor) or are unsupported.
- No globals parameters (`http_referer` etc.) on any op — matching the source spec, which lacks
  them; no equivalent of the published generator globals config.
- **Wire-name mapping**: identical policy to published, implemented in the codec layer instead of
  pydantic: `codec-plan.json` holds `{name, wire, required, fixed}` per field
  (`codec_runtime.py:141-184` does `getattr(value, field['name'])` on encode →
  `output[field['wire']]`, and `value.get(field['wire'])` on decode → `cls(**{field['name']: …})`).
  Verified rename inventory: **55 renamed fields across 37 of 489 models** — same pairs as
  published (`api_key`↔`apiKey`, `base_url`↔`baseUrl`, `model_id`↔`modelId`, `space_key`↔`spaceKey`,
  `ml_app`↔`mlApp`, `project_id`↔`projectId`, `instance_id`↔`instanceId`, `public_key`↔`publicKey`,
  …) plus `type_`↔`type` keyword handling (`BooleanCapability.type_`, 12 models). **All 75
  top-level parameter bindings have python name == wire name** (the source spec's query/path params
  are snake_case), so no parameter-level rename exists on either side; the divergence is confined to
  body/header fields, where both sides agree.
- Param type surface: query/path params are plain primitives or `Literal` enums
  (`models.py:3422`: `GetBenchmarksQueryMaxResults = int`; `GetAppRankingsQueryCategory =
  typing.Literal["coding", …]`); response numerics are `JsonNumber` (exact token preservation).

**Per-op parameter diff (the 42 emitted ops)** — mechanical comparison of our kw-only params vs
published business params:

- `get_user_activity`: published takes `request=` object whose TypedDict fields are
  `http_referer`, `x_open_router_title`, `x_open_router_categories`, `date_` (alias `date`),
  `api_key_hash`, `user_id`, `group_by`, `workspace_id` (`operations/getuseractivity.py:80-140`) —
  ours takes `date`, `api_key_hash`, `user_id` (matching the assembled spec's query params;
  published's `group_by`/`workspace_id` are not in the assembled spec). The published
  request-object style also hides the globals; ours has no globals at all.
- `get_benchmarks`: ours `source, task_type, arena, category, max_results` (5) vs published 9
  (`source, task_type, benchmark_type, include_run_config, search_engine, search_surface, arena,
  category, max_results`) — **4 published params missing ours-side** (assembled spec is narrower).
- `list_files`: ours `limit, cursor, workspace_id` vs published `limit, cursor, workspace_id,
  provider, after, after_id, before_id, order` — **5 missing ours-side** (spec drift).
- `query_analytics`: published flattens the body into ~10 kwargs (`metrics`, `classifier_dimensions`,
  `classifier_filters`, `dimensions`, `filters`, `granularity`, `group_limit`, `limit`, `order_by`,
  `time_range`); ours takes `body: models.QueryAnalyticsRequest | Unset` (closer to the wire schema,

- `create_byok_key`, `create_guardrail`, `create_observability_destination`, `create_workspace`,
  `bulk_*`, `submit_generation_feedback`, `exchange_auth_code_for_api_key`: published takes N flat
  kwargs, ours takes one `body:` kwarg (same wire body schema; shape differs).
- All list ops (`list_byok_keys`, `list_guardrails`, `list_key_assignments`,
  `list_member_assignments`, `list_guardrail_*_assignments`, `list`, `list_endpoints`,
  `list_observability_destinations`, `list_organization_members`, `list_presets`, `list_providers`,
  `list_workspaces`, `list_workspace_budgets`, `list_workspace_members`, `list_image_model_endpoints`):
  parameter sets match 1:1 (names + locations), except the four ops above and path-param-name
  difference `workspace_ref` (published) vs `id` (ours) for workspace budgets.
- `get_credits`, `get_analytics_meta`, `list_image_models`, `list_providers`, `get_task_classifications`,
  `get_app_rankings`, `get_rankings_daily`: parameter sets match 1:1.
- `delete_file`, `get_file_metadata`, `download_file_content`: ours `file_id` (path, required) +

## f. Response & model shapes

**Envelope preservation** — both sides keep the wire envelope; wrappers differ:

- Published: methods return `operations.<Op>Response` pydantic models whose fields mirror the
  response JSON (e.g. `GetCreditsResponse.data: GetCreditsData`); some ops return components
  directly (`analytics.get_user_activity` → `components.ActivityResponse`; `chat.send` →
  `components.ChatResult`). No HTTP metadata is exposed on success.
- Ours: every success is a frozen dataclass `operations.<Op>Status200` with `data` (the decoded
  response model **or** `bytes` for binary), plus `status: Literal[200]`, `headers`
  (`tuple[tuple[str, str], …]`), `content_type`, `links: tuple[Link, …]` — HTTP metadata is always
  present (`operations.py:13-19`). For `get_credits` the wire envelope `{data: {total_credits,
  total_usage}}` survives on both sides; ours just adds the metadata fields, so a port reads
  `result.data.data.total_credits` instead of `result.data.total_credits`.

**Field-by-field, five representative models:**

1. **GetCredits** — Published `operations.GetCreditsData`: `total_credits: float`, `total_usage:
   float` (wire names already snake_case; **no alias, no rename** — the hypothesized
   `totalCredits→total_credits` alias does **not** exist for this model). Ours
   `models.GetCreditsResponse200Data`: `total_credits: JsonNumber`, `total_usage: JsonNumber` —
   same names; type differs: published coerces to binary `float`, ours preserves the exact JSON
   number token (`json_runtime.JsonNumber`), refusing lossy float conversion.
2. **BYOKKey** — Published `components.BYOKKey` (13 fields): `allowed_api_key_hashes:
   Nullable[List[str]]`, `allowed_models: Nullable[List[str]]`, `allowed_user_ids:
   Nullable[List[str]]`, `created_at: str`, `disabled: bool`, `id: str`, `is_byok_only: bool`,
   `is_fallback: bool`, `is_required: bool`, `label: str`, `provider: BYOKProviderSlug`,
   `sort_order: int`, `workspace_id: Nullable[str]`, `name: OptionalNullable[str] = UNSET`.
   Ours `models.ByokKey` (12 fields): same names but `allowed_api_key_hashes/allowed_models/
   allowed_user_ids: list[str]` — **nullability dropped** (spec declares `nullable: true` for these
   three and `name`; published encodes it as `Nullable[...]`). `is_byok_only`/`is_required` absent
   from the assembled spec, hence from ours (spec drift, not a generator choice). Acronym casing
   differs: `BYOKKey` vs `ByokKey`.
3. **ActivityItem** — Published: `byok_usage_inference: float`, `completion_tokens: int`,
   `date_: str` (**alias `date`**), `endpoint_id: str`, `model: str`, `model_permaslug: str`,
   `prompt_tokens: int`, `provider_name: str`, `reasoning_tokens: int`, `requests: int`,
   `usage: float`, `workspace_id: NotRequired[str]`. Ours: identical field set and names except
   `date` (no rename needed in ours since generated modules don't import `datetime`), floats are
   `JsonNumber`, and `workspace_id` is absent (assembled spec lacks it). Ours adds
   `_extra_fields` preservation for undeclared keys; published pydantic config silently ignores
   unknown keys (default `extra='ignore'`).
4. **ObservabilityArizeDestination.config** (union of destination configs) — Published:
   `api_key: str [alias apiKey]`, `base_url: Optional[str] [alias baseUrl]`, `model_id: str
   [alias modelId]`, `space_key: str [alias spaceKey]`. Ours
   `models.ObservabilityArizeDestinationConfig`: `api_key`, `base_url`, `model_id`, `space_key`
   with codec-plan `wire` entries `apiKey`/`baseUrl`/`modelId`/`spaceKey` — **identical renaming
   behavior, different mechanism** (pydantic alias vs codec descriptor). `base_url` is required in
   ours, optional in published (assembled-spec drift).
5. **VaultSecret** (datetime case) — Published `components.vaultsecret`: `created_at: datetime`
   — ISO-8601 parsed into `datetime` via `utils/datetimes.py`; 11 component modules use `datetime`.
   Ours: **no `datetime` anywhere** (`grep datetime models.py`: 0 hits) — `format: date-time` and
   `format: uuid` fields are emitted as `str`. Ours never parses dates.

**Unions / unknown / optionality:**

- Published: TypedDict twins (`NotRequired` for optional, `total=False` semantics), `Nullable[T]`
  for required-nullable, `OptionalNullable[T]` for optional-nullable, pydantic unions with
  open-world fallbacks — `UnrecognizedStr`/`UnrecognizedInt` members appear in 141 component files
  so unknown enum/union variants decode into a str/int subclass instead of failing.
- Ours: closed world. Optionality is exactly two states: `T` (required) and `T | Unset` (optional);
  `None` only where the schema admits null — but see finding **F-1** below: `nullable: true` from
  the source spec is dropped, so several fields that can be `null` on the wire are typed `T` and a
  `null` payload raises `CodecError('invalid')`. Literal unions validate against the declared set
  (`codec_runtime.py:99-103`: unknown literal → `fail('value is outside the declared literal set')`);
  structural unions try each alternative against the declared schema and fail with `no source
  branch matches this native value` — there is **no Unknown/Unrecognized fallback**, so a server
  that adds a new enum value breaks decoding where the published SDK stays open.
- Extras: ours preserves undeclared keys in `_extra_fields` (closed models raise on collision);
  published drops them.

## g. Pagination, streaming, errors, webhooks

**Pagination**

- Published: **no auto-pagination surface**. `grep SyncPage|AsyncPage` over the wheel: 0 hits.
  List ops return one typed response; callers page manually with `offset`/`limit` kwargs
  (`api_keys.list(offset=…)`, `byok.list(offset=…)`). Cursor-based `listFiles` exposes `cursor`.
- Ours: direct paging is the same manual `offset`/`limit` story, **plus** generated iterator helpers
  for exactly one op: `iter_list_organization_members_pages(**kwargs)` (lazy page generator with
  offset continuation, stall detection → `SdkError('pagination-stalled')`) and
  `iter_list_organization_members_items(**kwargs)` (flattened items) — sync and async variants.
  No other op has iterators (no pagination descriptor in `protocol-plan.json` for the remaining
  list ops), so the auto-pagination surface is 1 op vs published's 0.

**Streaming**

- Published: `chat.send(stream=True)` (and presets/responses/images/embeddings/rerank variants)
  returns `eventstreaming.EventStream[components.ChatStreamChunk]` (async:
  `EventStreamAsync`) — an SSE helper with typed chunk events; `ChatResult` union covers the
  non-streaming case; overloads discriminate on `stream`.
- Ours: the machinery exists (`_streams.py`: `SyncStream`/`AsyncStream` with SSE + JSON-lines
  framer, item budgets, context-manager close semantics) and the runtime routes any response whose
  negotiated media representation is a stream into it (`_runtime.py:550-553, 634-637`). However,
  **every streaming-capable operation was refused** (`http-stream-item-schema-required` on
  `sendChatCompletionRequest`, `createResponses`, `createEmbeddings`, `createImages`, `createRerank`,
  `POST /messages`) — so **zero emitted operations return a stream**. The streaming surface is
  unreachable from the public API today.

**Errors**

- Published hierarchy (`errors/`): `OpenRouterError` (base, carries `message`, `status_code`,
  `body`, `headers`, `raw_response`) → 17 per-status classes generated from declared 4XX/5XX
  responses (`BadRequestResponseError`, `UnauthorizedResponseError`, `ForbiddenResponseError`,
  `NotFoundResponseError`, `ConflictResponseError`, `PaymentRequiredResponseError`,
  `TooManyRequestsResponseError`, `RequestTimeoutResponseError`, `UnprocessableEntityResponseError`,
  `PayloadTooLargeResponseError`, `ProviderOverloadedResponseError`, `InternalServerResponseError`,
  `BadGatewayResponseError`, `ServiceUnavailableResponseError`, `GatewayTimeoutResponseError`,
  `GoneResponseError`, `EdgeNetworkTimeoutResponseError`, each with a typed `…ErrorData` payload),
  plus `OpenRouterDefaultError` (fallback for unmatched 4XX/5XX), `NoResponseError` (no response
  received — does **not** extend `OpenRouterError`), and `ResponseValidationError` (pydantic
  mismatch, exposes `.cause`). Errors are raised per-status inside every method; matching is
  content-type aware (`match_response`).
- Ours: two orthogonal families. (1) `operations.<Op>Status<4xx/5xx>` subclasses of
  `ApiError[T]` — one per declared error response **per operation**, generic over the typed data
  model, carrying `status`, `data`, `headers`, `source`, `content_type`, `typed_headers`, `links`
  (`operations.py:21-37` etc.); the client raises them from `_call` via `raw.result`
  (`_runtime.py:266-283`). (2) `SdkError` for **everything that is not a declared API response**:
  kinds `transport`, `request-validation`, `request-representation`, `response-decoding`,
  `resource-limit`, `authentication`, plus codes like `http-path-parameter`,
  `http-required-parameter`, `http-server-choice`, `pagination-stalled` (`_types.py:20-30`,
  `_runtime.py`, `_auth.py:118`, `_client.py:459-470`). There is **no** no-response sentinel class
  (transport failures become `SdkError('transport', …)`) and no shared base for the two families.
- Net: published = narrow exception types you can `except UnauthorizedResponseError`; ours =
  per-op-per-status types you must catch via `operations.GetCreditsStatus401` / broad `ApiError` /
  `SdkError` — comparable coverage of declared statuses, different ergonomics, and ours adds
  source-anchored diagnostics the published SDK lacks.

**Webhooks**

- Published: none (no webhooks module in the wheel).
- Ours: none (no webhook verification/emission surface).
- Parity: absent on both sides.
